# 上手第一周行动清单

> 面向刚接手媒介数据分析岗位的人，按天排，照着走。
> 核心原则：**第一周的目标不是做出成绩，是不出错、快速搞清楚状况。**

---

## Day 1：搞清楚"我在哪、我干什么"

### 上午：环境与人

- [ ] 拿到公司邮箱、内部系统、共享盘的权限
- [ ] 搞清楚汇报线：我的直属上级是谁？我的产出交给谁？
- [ ] 认识三类人：
  - **同组的数据分析师**（遇到问题问他们）
  - **对接的媒介策划/客户执行**（他们是我的下游）
  - **数据源对接人**（数据从哪来，谁负责导）

### 下午：业务与数据

- [ ] 我负责哪些客户？每个客户是什么行业、什么产品？
- [ ] 每个客户的 KPI 是什么？谁定的？考核周期？
- [ ] 日报/周报/月报分别什么时候交？交给谁？用什么模板？
- [ ] **要一份历史交付的报告样本**——这是了解期望值最快的方式

### 关键问题清单（当天必须问到答案）

1. 公司主用的数据源是什么？（CSM / 勾正 / 尼尔森）
2. 默认人群口径是什么？（4+ / 25-54 / 客户自定义）
3. 默认区域口径是什么？（全国网 / 城域网 / 省网）
4. 数据是怎么到我手上的？（系统导出 / 别人给 / 我自己拉）

> 💡 **第一天问问题不丢人，第三周还在问基础问题才丢人。**
> 准备一个本子，所有答案记下来。

---

## Day 2：把工具接上真实数据

- [ ] 拿到一份真实的投放明细表
- [ ] 打开 `config/field_mapping.yaml`，把真实表头加到对应字段的 `aliases` 里
- [ ] 用「🔍 数据质量检查」页跑一遍，看能不能正常读入
- [ ] 记录下所有"未识别的列"，判断哪些是有用的，补进配置

### 字段映射怎么改（举例）

假设你的真实表头是"投放日期"、"媒体名称"、"实际花费"：

```yaml
placement:
  date:
    aliases: [日期, 播出日期, 投放日期, 投放日期]   # ← 已经有了
  channel:
    aliases: [频道, 频道名称, 媒体, 媒体名称]      # ← "媒体名称"已经有了
  cost:
    aliases: [花费, 费用, 金额, 实际花费]          # ← "实际花费"已经有了
```

大部分常见写法已经预置了。如果有特殊的，加一行就行。**不用改代码。**

---

## Day 3：校准基准数据

这一步决定了工具的所有测算结果是否可信。

- [ ] 找同事要一份**频道 CPRP 基准表**（历史成交价，不是刊例价）
- [ ] 找一份**频道平均收视率**数据
- [ ] 打开 `config/benchmarks.yaml`，替换 `channels:` 下面的值
- [ ] 确认目标人群基数（`universe:` 那一段）
- [ ] **把 `verified: false` 改成 `verified: true`**

改完之后，页面顶部那个"占位基准"的警告就消失了。

### 如果要不到完整基准怎么办

退而求其次，用**历史投放数据反算**：

```
某频道 CPRP = 该频道历史总花费 ÷ 该频道历史总 GRP
```

用最近 3~6 个月的数据算，比用行业估算值靠谱得多。

## Day 4：跑通第一份报告

- [ ] 用「📊 日报周报月报」页生成一份报告
- [ ] **逐个数字跟历史报告核对**，确认口径一致
- [ ] 对不上的地方，找出原因（是我的口径错了，还是历史报告口径不同）
- [ ] 把自动生成的结论改写成自己的话

> ⚠️ **不要把工具生成的报告直接交出去。**
> 第一份报告一定要手工核对每个数字。
> 确认无误后，再逐步信任自动化。

---

## Day 5：建立自己的检查习惯

- [ ] 把「🔍 数据质量检查」页底部的自查清单打印出来贴在显示器旁
- [ ] 复盘这一周踩过的坑，看哪些能变成质检规则
- [ ] 整理一份"我负责客户的常见数据问题清单"

### 交付前的最后三个动作（养成肌肉记忆）

1. **总数对账**：报告里的总花费 = 结算单的总花费？
2. **口径复核**：人群/区域/数据源，跟客户约定的一致？
3. **结论过一遍**：每句话我自己信不信？被追问能不能答上？

---

## 第一周要避开的五个坑

### 坑 1：不问口径就出数

**后果**：数字全错，还不知道错在哪。
**对策**：拿到任何数据，先问"人群口径、区域口径、数据源"。

### 坑 2：把 GRP 和 TRP 混着比

**后果**：结论完全反了，专业形象崩塌。
**对策**：每个数字都标注口径，报告里写清楚。

### 坑 3：各频道到达率直接相加

**后果**：净到达率虚高一大截，被同事当场指出。
**对策**：用 Sainsbury 公式去重，工具已经内置。

### 坑 4：发现数据异常直接改掉

**后果**：抹平了真实的业务信号，可能掩盖重大问题。
**对策**：**先问业务，再决定处理方式。** 异常不等于错误。

### 坑 5：报告只有数字没有结论

**后果**：被评价为"只会拉数的"，成长天花板很低。
**对策**：每份报告至少给一条带行动建议的洞察，哪怕不成熟。

---

## 一句话总结第一周

> **第一周不要试图证明自己有多厉害。**
>
> 把口径搞清楚、把数据对准、把流程跑通、把问题问明白。
>
> 这四件事做扎实，第二周开始你就能比很多人跑得快。

## 附：每天下班前的五分钟

问自己三个问题，记在本子上：

1. 今天学到的**最重要的一个业务知识**是什么？
2. 今天遇到的**最卡壳的一个问题**是什么？解决了吗？
3. 明天**最优先要做的一件事**是什么？

一周后回看这些记录，你会清楚地知道自己的成长曲线在哪。
